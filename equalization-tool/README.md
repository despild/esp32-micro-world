# Equalization Tool · 휴대용 이퀄라이징 압력 측정기

ESP32와 호스 연결형 압력센서로 만드는 육상 이퀄라이징 연습용 기기입니다. **HX710B + MPS20N0040D용 펌웨어, OLED 기본 그래프, 택트스위치 2개 메뉴, Wi-Fi/웹 QR, 브라우저 실시간 그래프를 구현했습니다.** 센서·버튼은 아직 물리 연결 전이므로 압력 정확도와 실제 버튼 배선은 조립 후 검증합니다. 배터리 회로와 BLE는 미구현입니다.

조사 기준일: 2026-11-11, Asia/Seoul.

## 개발 위치와 센서 미연결 표시

개발 원본은 이 저장소의 `equalization-tool/`입니다. 2026-11-12에 포트폴리오 프로젝트의 `.local/eq-sample/`에 임시로 만들어졌던 변경을 이곳으로 옮겼습니다. 이후 펌웨어, 웹, 테스트, 샘플 패턴은 모두 이 폴더에서 수정합니다. 이전 작업본 33개 파일은 해시를 대조해 로컬 `output/migration-20261112/`에 보관하고, 포트폴리오 쪽 임시 폴더는 제거했습니다. 로컬 캐시와 환경별 Arduino 설정은 배포 소스에 포함하지 않습니다.

**1.1의 센서 미연결 화면**은 OLED와 웹 모두 가압·유지·해제 샘플 파형을 반복 표시합니다. OLED는 `DEMO NO SENSOR`, 웹은 `샘플 압력 패턴`으로 구분합니다. 짧은 반복, 두 번 연속 가압, 긴 유지와 해제를 포함하는 12초 예시이며 실제 측정 기록이나 목표 압력이 아닙니다. 실제 센서가 들어오면 RAW 측정으로 전환하고, 영점·교정 후 kPa를 표시합니다.

샘플은 표시 전용입니다. API의 `raw`와 `pressure`는 센서가 없을 때 계속 `null`이고, 샘플 CSV 저장·영점·교정은 사용할 수 없습니다. 일시정지한 샘플도 센서 연결 시 해제됩니다. 폰과 ESP32의 통신이 끊기면 웹 샘플 애니메이션도 중단합니다. 파형 원본은 [`demo-pattern.json`](demo-pattern.json) 하나이며 OLED와 웹에 함께 반영됩니다.

2026-11-12에 **1.1을 실제 보드에 업로드**하고 내부 검증 25개, OLED 샘플 이동·멈춤·재개, 메뉴·QR·Wi-Fi 전환, 3개 HTTP 경로를 확인했습니다. USB 진단 응답 35건과 브라우저 모의 전송 시나리오 24개도 통과했습니다. 사용자는 Android Chrome 웹과 OLED 모두에서 샘플 파형이 보임을 확인했습니다. 마지막 업로드는 같은 화면에 USB 진단 전송 보완만 추가한 버전입니다. 실제 압력센서·버튼과 충전식 전원 회로는 아직 연결 전입니다.

웹은 밝은 배경에 파형을 중심으로 배치하고 교정 설정을 접었습니다. Impeccable 스킬과 실행 엔진을 설치해 소스·모바일·데스크톱 검사를 수행했습니다. 주요 지적 사항은 0개이며 데스크톱 글자 크기 위계에 관한 참고 의견 1개는 조밀한 측정 도구에 맞춘 의도적 선택으로 기록했습니다. [디자인 기준](DESIGN.md), [디자인 검사 기록](verification/impeccable-design.json), [모바일 샘플 화면](verification/equalization-demo-images/web-demo-mobile.png)에서 확인할 수 있습니다. 웹 스크린샷은 모의 전송 테스트 화면입니다.

## 이퀄툴 펌웨어와 조립 안내

- [필요 부품과 GPIO 배선도](wiring-and-parts.md): 센서 OUT→GPIO4, SCK→GPIO3, 버튼 A→GPIO0, B→GPIO1.
- [펌웨어 사용법과 메뉴 트리](firmware/EqualizationTool/README.md): 기본 그래프, A=메뉴/다음, B=선택, QR은 PHONE 메뉴.
- [1.1 검증 기록](verification/equalization-demo-1.1.json): 빌드·장치·브라우저 검증 결과 및 미검증 항목. [이전 1.0 기록](verification/equalization-firmware.json)도 보존합니다.
- 폰은 **EQ-C3 / eqtest32 → http://192.168.4.1**. 첫 버전은 부팅 시 Wi-Fi를 켜고 메뉴에서 끌 수 있습니다.
- 센서 연결 후 영점과 실제 기준 압력으로 교정합니다. 교정 전 RAW, 센서 미연결 시 샘플 표시와 미연결 안내, ADC 포화 시 오류 상태를 표시합니다. 샘플을 실제 센서 측정값으로 취급하거나 임의 kPa로 환산하지 않습니다.

## 앞서 완료한 연결 테스트

기존 `WebQrTest`에서는 **EQ-C3 / eqtest32**에 연결해 **http://192.168.4.1**을 열고 OLED의 `PHONE OK`까지 확인했습니다. 이 별도 연결 테스트 펌웨어에는 압력 측정이 없습니다. 새 이퀄툴 펌웨어는 같은 AP 설정과 QR을 사용합니다.

빌드·업로드, 장치 AP 시작, OLED I²C 응답, 두 프레임버퍼의 QR 디코딩, 내부 TCP HTTP 응답을 확인했습니다. 실제 Android Chrome에서도 **로컬 네트워크 권한 허용 후 웹 접속**을 확인했고 보드의 웹 요청이 1초마다 증가했습니다. 폰의 버튼을 눌렀을 때 OLED에 **PHONE OK가 표시되는 것까지 사용자 확인**을 마쳤습니다. 휴대폰 카메라로 작은 OLED QR을 읽는 시험은 별도로 남아 있습니다. 기존 게임 진행 상태와 전체 플래시는 로컬에 백업했습니다. [실행·복구 가이드](firmware/WebQrTest/README.md), [장치 검증 기록](verification/web-qr-test.json), [폰 연결 기록](verification/phone-connection.json)

## 요구사항

- 호스 연결이 쉬운 센서로 입 또는 코 쪽의 상대압 측정.
- 기기 화면에 압력 표시. 작은 택트스위치로 화면 전환과 기능 설정.
- 별도의 물리 온오프 스위치.
- 휴대폰에서 실시간 확인 및 기록. ESP32 내부 웹서버와 Wi-Fi/QR 접속을 검토하며 BLE도 확장 후보로 유지.
- USB 보조배터리로 시험 가능하고, 최종적으로 충전식 리튬이온/리튬폴리머 배터리 사용.
- 기존 `esp32-micro-world` 저장소의 `equalization-tool/` 아래에서 관리.
- 비용을 최소화하면서 측정 안정성, 장기 내구성, 배터리 사용시간을 확보.

## 제안 구성

| 부분 | 1차 제안 | 선정 상태 |
|---|---|---|
| MCU | 현재 사용 중인 ESP32-C3 mini 재사용 | BLE 지원. 실제 보드 회로와 여유 GPIO 확인 필요 |
| 양방향 센서 비교 후보 | XGZP6897D 계열, I²C·호스 포트·**양방향 ±10 kPa** 옵션 | 양압/음압 기능이 필요할 때 비교. 상한이 충분한지는 실측 필요 |
| 보유 센서 활용 | BMP180 + 밀폐 챔버 + 사용 직전 영점 조정 | 초기 시험 대안. 양압 상한과 누설·결로 검증 필요 |
| 1차 양압 시제품 센서 | MPS20N0040D + HX710B 호스형 모듈 | Reddit에서 사용한 모듈과 동일하다고 확인. 명목 0–40 kPa, 교정·유효 범위·40 SPS 검증 필요. 음압 미보장 |
| 범위/매체 대안 | 공급 가능한 더 넓은 양방향 옵션 또는 Honeywell ABP2 | 범위 부족·습기 시험 결과에 따라 비교. ±25 kPa를 필수 사양으로 확정하지 않음 |
| 화면 | 보유 0.42인치 OLED에 기본 그래프 | 72×40으로 구현. 더 큰 화면은 추후 선택 |
| 폰 연결 | 필요한 때만 켜는 Wi-Fi AP + 로컬 웹을 우선 검토 | 72×40 OLED QR은 스캔 검증 필요. QR 스티커·SSID/IP 표시로 보완 |
| 조작 | 소형 순간동작 택트스위치 2개 | A 메뉴/이동, B 선택/화면 멈춤. GPIO0/1 확정 |
| 전원 | 보호회로 포함 1셀 3.7 V, 1,000 mAh 안팎 배터리 | 완충 4.2 V 계열. 충전 허용전류 확인 |
| 충전 | BQ25185 + 5 V 승압 통합 모듈 우선, BQ24074 분리 구성 대안 | **충전 중 사용 가능**. 정확한 팩 허용 전류/발열/입력 예산 검증 필요 |
| 온오프 | 통합 모듈 EN–GND 슬라이드 스위치 | 접점 닫힘=출력 OFF·충전 유지. BQ24074 대안은 부하 경로 차단 |
| 전압 변환 | 보드 입력에 맞춘 레귤레이터 | 현재 보드 회로 확인 전 직결 핀을 지정하지 않음 |

현재 우선순위와 절감 방안은 [비용·안정성 계획](cost-and-reliability.md)에 정리했습니다. 센서 상세 사양과 근거는 [하드웨어 조사](hardware-research.md), 연결 방식과 버튼·BLE·전원 동작은 [설계안](design-notes.md)에 있습니다. 표의 범위는 **기기의 측정 범위**이며 사람에게 권장하는 이퀄라이징 압력이 아닙니다.

보유 센서를 활용하는 방법은 [BMP180 시제품](bmp180-prototype.md), 앱 없이 폰에서 보는 방법과 작은 화면의 한계는 [로컬 웹·QR 접속](web-connectivity.md)에 정리했습니다. BMP180 측정은 구현 전입니다. 현재 구현 기준은 위 HX710B 펌웨어와 배선 가이드입니다.

사용자 지정 모듈의 조건과 비교, 연결된 예제 라이브러리의 클럭·교정·단위 문제는 [HX710B 검토](hx710b-review.md)에 있습니다. 양압 시제품은 이 모듈을 우선 검증하고, XGZP6897D는 양방향 요구를 충족해야 할 때의 비교 후보로 유지합니다.

## 진행 순서

1. 정확한 보드 모델, 센서 주문 옵션, 배터리/충전 전류를 확정.
2. USB 전원으로 센서·호스·화면·버튼의 기본 동작 확인.
3. 공기압 기준기와 비교하여 영점, 누설, 반복성, 응답 지연 확인.
4. 구현한 로컬 웹과 실제 센서 파형을 함께 확인. BLE는 선택 모드로 검토.
5. 배터리·충전·전원 스위치 통합 후 충전 중/배터리 동작·대기전류 실측.
6. 케이스와 호스 고정부 제작.

현재 구현은 `firmware/EqualizationTool/`, `web/`, `tools/`에 있습니다. `firmware/WebQrTest/`는 기존 연결 진단용입니다. 정확도·내구성·배터리 회로 검증을 마친 완제품은 아닙니다.
